# 우리말 사전 편찬

교사는 메인 앱에서 수업을 진행하고, 학생은 QR·링크로 모바일 전용 화면에 입장해 공동 사전을 만듭니다.

**표현 등록 → 원래 표현 상호 평가 → 순화어 제안·평가 → 교사 승인 → 최종 사전 편찬**

- 교사 화면: 메인의 사전 입장에서 완성된 사전을 읽고, **사전 열기 / 새 사전 만들기**로 수업을 관리합니다. 모으기·평가하기·순화하기마다 해당 단계의 **학생 입장 QR·링크**를 제공합니다. QR은 로컬 코드로 생성하며 링크를 외부 QR 서비스로 보내지 않습니다.
- 사전 보기는 **단어별 보기**가 기본이며, 순화어 가나다순으로 원래 표현·순화어·뜻을 검색합니다. **사전별 보기** 탭에서는 제목으로 완성된 사전을 찾습니다. 제목은 1~80자로 자유롭게 정하며, 같은 제목으로 별개의 사전을 만들 수 있습니다. 기존 사전 제목은 `1-7 파이팅`입니다.
- 사전 둘러보기는 익명 계정 생성 없이 조회합니다. 교사가 승인한 항목만 공개합니다. 현재 버전은 `supabase/open-dictionary.sql` 전체로 설치·업데이트합니다. 이전 승인 버전에는 `supabase/student-portal-update.sql` 다음 `supabase/realtime-update.sql` 순서로 적용할 수도 있습니다. 과거 기능 패치는 현재 설치 이후 재실행하지 않습니다.
- 학생 첫 입장: **닉네임(1~20자) 설정 → 입장하기 → 활동 시작**입니다. 같은 학생 접속에서는 다음 입장부터 닉네임을 재사용합니다. 표현의 작성자와 순화어의 작성자에 자동 연결하며, 순화어 폼에 매번 닉네임을 입력하지 않습니다. 서버가 입장 시 정한 이름을 적용하고 최종 카드에는 제안별 스냅샷을 표시합니다. 기존 예시 닉네임도 보존합니다.
- 실시간: Supabase Database Broadcast로 변경 알림을 받고, 각 접속의 권한으로 최신 응답을 다시 조회합니다. 교사 화면에 입장 학생 수·표현·별점·순화어 건수와 참여 인원을 표시합니다. 입력 폼은 실시간 갱신으로 교체하지 않아 초안과 입력 위치를 유지합니다. 연결 장애 시 재연결과 제한된 주기 조회로 복구합니다.
- 작성 중인 사전 제목·표현·순화어·닉네임은 같은 탭의 임시 저장으로 복구합니다. 저장 실패 후 재시도는 같은 등록 ID를 사용해 중복을 막습니다. 단계·검색·페이지는 주소에 남아 새로고침 후에도 유지됩니다.

- 학생 화면: `student.html#class=...&stage=collect|rate|refine&join=...`로 입장합니다. **표현 등록 / 평가하기 / 순화하기** 내비게이션은 모바일 상단에 고정되고, 현재 단계를 표시합니다. 세 단계는 자유롭게 이동하며 입력 초안을 복원합니다. 학생 화면에는 사전 생성·승인·관리자 메뉴가 없습니다.
- 원래 표현: 뜻과 순화가 필요한 이유를 등록하고, 다른 학생이 **순화 필요성**을 1~5점으로 평가합니다.
- 같은 표현도 **서로 다른 학생이 각각 등록**할 수 있습니다. 모으기·평가하기에서는 각각의 뜻풀이와 원래 표현 평가를 보존합니다. **순화하기에서는 같은 사전의 중복 표현을 한 카드로 묶고, 모든 순화어 후보를 별점순으로 나열**합니다. 앞뒤 공백과 영문 대소문자를 제외한 원래 표현이 같으면 같은 묶음이며 다른 사전과는 섞이지 않습니다.
- 순화어: 같은 표현 묶음에 원래 표현 평가가 1개 이상 모이면 새 표현·뜻·이유·예문·닉네임을 제안합니다. 다른 학생이 각 후보의 뜻 전달력과 자연스러움을 1~5점으로 평가합니다. 후보마다 닉네임과 별점은 독립적입니다.
- **승인하기**는 순화하기 다음, 최종 사전 앞에 있는 교사 전용 단계입니다. **승인 대기중 / 승인 완료** 탭을 제공하며, 대기 목록에는 각 원래 표현에서 평가가 1개 이상인 **평균 평점 1위 후보를 모두** 표시합니다. 공동 1위도 포함하고 4점 제한은 없습니다. 승인은 서버에서 교사 권한과 현재 순위를 다시 확인합니다.
- 최종 사전: 교사가 **승인**하면 바로 편찬 완료로 바뀝니다. 이후 별점이나 순위가 바뀌어도 유지하며 **승인 취소**할 때만 공개 사전에서 제외합니다. 기존 편찬 항목과 별점은 보존하고 승인 완료 목록에 표시합니다.
- 자기 표현은 평가할 수 없습니다. 같은 학생이 다시 평가하면 기존 별점 한 개가 갱신됩니다. 같은 사전의 원래 표현 묶음당 자신의 순화어는 한 개를 제안할 수 있습니다.
- 교사는 **비밀번호 없이** 최고 평점 후보를 승인·취소합니다. **관리자 로그인** 비밀번호만 **`admin123`**입니다. 로그인 후 사전 삭제, 원래 표현과 순화어의 수정·삭제, 용량 조회를 할 수 있습니다. 서버가 관리자 권한을 검사하며 비밀번호는 해시로 검증합니다. 인증은 8시간, 5회 실패 시 15분 제한입니다.
- 관리자 수정은 작성자 ID·별점·승인 상태를 보존하고 편찬 결과에도 즉시 반영됩니다. 원래 표현 삭제는 연결된 후보·별점까지, 순화어 삭제는 해당 후보·별점·편찬 항목만 연쇄 삭제합니다. 사전 삭제는 학생 입장 링크·참여 기록까지 함께 삭제하며 다른 사전은 보존합니다.

## Supabase 연결 설정

현재 앱은 서울 리전의 무료 `korean-dictionary` 프로젝트에 연결되어 있으며, 사전 데이터베이스를 설치했습니다. 다른 프로젝트로 이전하거나 새 환경에 설치할 때는 다음 순서를 따릅니다.

1. Supabase에서 **Free 요금제** 프로젝트를 만들거나 기존 무료 프로젝트를 엽니다. 현재 프로젝트가 일시 중지되어 있다면 대시보드에서 복구합니다. 유료 플랜으로 업그레이드하지 않습니다.
2. 프로젝트의 **SQL Editor**에서 [`supabase/open-dictionary.sql`](supabase/open-dictionary.sql) **전체를 한 번 실행**합니다. 이 파일만으로 새 구조가 설치됩니다. 이전 수업 테이블은 삭제하지 않습니다. 이미 설치한 뒤 다시 실행해도 새 사전의 자료는 유지됩니다.
3. **Authentication → Sign In / Providers → Anonymous Sign-Ins**를 켭니다. 학생에게 로그인 입력을 받는 기능이 아니라 서버가 작성자·평가자를 구분하기 위한 익명 접속입니다.
4. 프로젝트의 **Connect / API 설정**에서 Project URL과 **publishable key**를 확인해 [`site/config.js`](site/config.js)에 넣습니다.

```js
window.APP_CONFIG = Object.freeze({
  supabaseUrl: 'https://프로젝트_ID.supabase.co',
  supabasePublishableKey: 'sb_publishable_...'
});
```

5. `site/config.js` 변경을 GitHub `main`에 commit/push합니다. **Actions → Deploy GitHub Pages**의 `test`와 `deploy`가 성공하면 연결 설정이 사이트에 반영됩니다.
6. 테스트 사전을 만들고 학생 입장 QR·링크로 두 브라우저에서 닉네임 설정·등록·평가·순화어 제안을 진행합니다. 교사 화면에서 로그인 없이 승인한 뒤, 관리자 로그인 `admin123`으로 수정·삭제를 확인하고 테스트 사전을 정리합니다.

브라우저에 공개되는 파일에는 publishable 키만 사용합니다. `service_role`, secret 키, DB 비밀번호는 넣지 않습니다. 브라우저 데이터 삭제나 시크릿 창·다른 기기는 다른 익명 참여자로 인식합니다.

## 무료 용량 보호

2026-11-06에 확인한 [Supabase Free 요금제](https://supabase.com/pricing)의 DB 한도는 500 MB, uncached egress는 5 GB, MAU는 50,000입니다. 이 앱은 텍스트 DB와 익명 인증만 사용하며 파일 저장소·Edge Functions를 사용하지 않으며 수업 중 실시간 변경 알림에 Realtime Broadcast를 사용합니다.

- 앱의 **DB 저장 보호 한도는 450,000,000바이트(450 MB)**입니다. 모든 학급·표현·별점·순화어 INSERT/UPDATE 앞에서 서버가 `pg_database_size()`로 실제 프로젝트 DB 크기와 여유 공간을 확인합니다.
- 같은 트랜잭션 잠금으로 동시 쓰기를 직렬화합니다. 클라이언트 검사를 우회해도 테이블 트리거가 한도 도달 시 저장을 거절합니다. 일반 사용자는 테이블에 직접 쓰거나 제한 값을 변경할 권한이 없습니다.
- 한도에 도달하면 학생의 새 저장·평점 변경·교사 편찬을 막고 안내합니다. **기존 자료 조회와 관리자 로그인·학급 삭제는 가능**합니다.
- DB 전체 크기에는 이 앱 외의 테이블도 포함됩니다. 삭제한 행의 공간은 PostgreSQL이 재사용하므로, 삭제 직후 파일 크기가 줄어들지 않을 수 있습니다. 그런 경우 저장 차단이 유지될 수 있으며 관리자 유지보수가 필요합니다. [DB 크기 설명](https://supabase.com/docs/guides/platform/database-size)
- 이 장치는 **DB 저장 용량**을 보호합니다. 프로젝트 전체 트래픽·MAU를 청구 시스템과 동일하게 실시간 측정하는 장치는 아닙니다. 다른 무료 항목은 Supabase Free 요금제 자체 제한을 따릅니다. 앱은 업그레이드나 유료 초과 사용을 활성화하지 않습니다.
- 조회는 페이지 단위로 제한하며 변경 알림을 합쳐 최신 자료를 조회하고, 학생의 등록 화면과 평가 화면은 필요한 필드만 읽습니다. Free 플랜을 유지하고 Supabase Usage에서 다른 항목도 확인하세요. [Egress 설명](https://supabase.com/docs/guides/platform/manage-your-usage/egress)

## 구조와 권한

```text
class_dictionaries
└─ dictionary_words
   ├─ dictionary_word_ratings
   └─ dictionary_revisions (교사 선택 여부 포함)
      └─ dictionary_revision_ratings

dictionary_settings        # 비밀번호 해시, 저장 한도; 사용자 직접 접근 불가
dictionary_admin_sessions  # 인증 만료·실패 제한; 사용자 직접 접근 불가
```

앱은 제한된 `dictionary_*` RPC로만 DB를 사용합니다. 각 함수가 익명 인증, 작성자, 별점 범위, 단계 조건, 관리자 권한을 검사합니다. 테이블은 RLS를 활성화하고 `anon`·`authenticated`의 직접 읽기·변경 권한을 회수했습니다. 공개 사전과 사전 목록은 로그인 세션 없이 조회할 수 있으며, 참여 시 익명 세션을 자동 발급합니다.

기존 `supabase/schema.sql`, `permissions-update.sql`, `lesson-flow-update.sql`은 이전 차시형 앱의 설치 자료로 보관합니다. **현재 버전은 `open-dictionary.sql`을 사용하세요.** 이전 버전의 수업 자료를 새 공개 학급 사전으로 자동 복사하지 않습니다.

## 로컬 검증

```sh
npm ci
npm run check
npm test
npx playwright install chromium
npm run test:browser
```

DB 테스트는 PGlite(PostgreSQL)에서 실제 SQL, 비밀번호 해시, 서버 권한, 용량 제한 트리거와 연쇄 삭제를 실행합니다. 브라우저 테스트는 학생 두 명과 관리자 한 명을 분리해 전체 편찬 흐름, 모바일, 저장 실패 재시도, 무료 용량 차단, 삭제를 확인합니다. 인증 세션 발급과 HTTP 전송만 테스트용으로 대체하며 **운영 Supabase 연결 성공을 뜻하지 않습니다.**

이미 설치된 Chromium은 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 환경 변수로 지정할 수 있습니다. `test-results/`에 검증 스크린샷을 저장합니다.


학생과 교사의 인증 저장 키를 분리합니다. 학생 입장 기록은 서버가 관리하며 학생 접속의 승인·다른 사전 참여를 제한합니다. 교사 승인은 비밀번호 없는 메인 앱 접속을 신뢰하는 방식입니다. 관리 작업은 별도 비밀번호 인증이 항상 필요합니다. 실시간 채널은 변경 종류만 전송하고 닉네임·본문·사용자 ID·입장 토큰은 전송하지 않습니다.
